# ADR 0012: Prisma 7 with the node-postgres driver adapter

**Status:** Accepted

## Context

Prisma 6 bundled a Rust query engine and read the connection string from `schema.prisma`. Its CLI also carried the only advisory that `npm audit --omit=dev` reported (`deepmerge-ts`, pinned exactly inside `@prisma/config`). Prisma 7 removes the Rust engine: queries go through a JavaScript driver adapter, configuration lives in `prisma.config.ts`, and the client is generated as TypeScript into the source tree.

## Decision

Upgrade to Prisma 7.10 (the latest stable release; 8.0 is still a release candidate).

- The `prisma-client` generator emits ESM TypeScript to `apps/api/src/generated/prisma` (gitignored, regenerated by `npm run build` and in CI). `tsc` compiles it into `dist`, so the runtime image no longer copies `node_modules/.prisma`.
- `@prisma/adapter-pg` drives a `pg.Pool`. `lib/prisma.ts` sets `max` from `DB_POOL_SIZE`, honours a legacy `connection_limit` URL parameter, and passes `?schema=` as the adapter's schema.
- `prisma.config.ts` owns the datasource URL. It is optional there so `prisma generate` works in the Docker build without a database.

## What changed in behaviour (and how we found it)

- **Unique-violation details moved.** With adapters, P2002 errors carry `meta.driverAdapterError.cause.constraint` instead of `meta.target`. The registration test ("duplicate username returns a field error") caught it. `core/tx.ts#uniqueTarget` reads both shapes.
- **`migrate diff` flags were renamed** (`--from-config-datasource`, `--to-schema`). The drift script had hidden stderr, so it would have passed silently. It now lets errors through, and we checked it fails on a deliberately drifted schema.
- Raw SQL (pgvector, `tsvector`, advisory locks, `FOR UPDATE SKIP LOCKED`), interactive transactions and the BullMQ/outbox tests passed unchanged: 134 of 134 API tests.

## Consequences

- No native engine binary: smaller images, no `binaryTargets`, no OpenSSL coupling.
- Pool behaviour is now node-postgres', which is well understood and observable.
- `npm audit --omit=dev` is clean.
